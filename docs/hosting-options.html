Canvas Notes: five other ways to host it

Different servers, databases and file storage, compared for you and your friends · 1 November 2026 · prices are rough monthly estimates in USD

Today: everything on one disk

Yes, all data is on a disk: the database file and the uploads folder sit in canvasnotes/data on your laptop. The plan so far moves that same folder to one Lightsail server's disk, with backups in S3. The options below move the database, the files, or both off the server's disk.

Two parts can move separately. The database (small: accounts, boards, card text, ≈ 20 MB) and the files (big: images and videos, 2.9 GB). Files are the part that grows, so moving them to object storage (S3, R2) is the most useful first step in every option.

1Lightsail server + files in Amazon S3 Smallest step from today

ServerOne Lightsail server, 1–2 GB, same Node program
DatabaseSQLite file on the server (as today), streamed to S3 by Litestream
FilesS3 bucket; the server hands the browser a short-lived signed link to upload or view
Cost≈ $8–14 / month (server $7–12, S3 ≈ $0.07 for 3 GB, requests pennies)
Code changeSmall: only the upload, download and clean-up parts talk to S3 instead of the folder
LearnS3, signed URLs, IAM permissions, Litestream
Good
  • Disk never fills up: S3 has no size limit
  • Files survive even if the server dies
  • Cheapest real setup
Watch out
  • Still one server: if it is down, the app is down
  • Database still lives on that server's disk (backed up)

2Containers + managed Postgres (classic AWS) How most companies run apps

ServerOur Docker image on ECS Fargate (AWS runs it; can run 2+ copies)
DatabaseRDS PostgreSQL: AWS handles backups, updates, failover
FilesS3, served through CloudFront (a CDN, so images load fast anywhere)
Cost≈ $35–55 / month (Fargate ≈ $9, RDS small ≈ $13–15, load balancer ≈ $17, rest small)
Code changeMedium: database queries move from SQLite to Postgres; files to S3
LearnDocker, ECS, RDS, VPC networking, CloudFront, load balancers — the most "real AWS"
Good
  • Survives one server dying; can grow to many users
  • Database backups and restore to any minute
  • Skills used at most jobs
Watch out
  • Most expensive at your size
  • Most moving parts to set up (networking, security groups)

3Serverless AWS: Lambda + DynamoDB + S3 Pay only when used

ServerNo server: each request runs a small Lambda function
DatabaseDynamoDB: key = (user, card id), value = the card
FilesS3; the app itself is also served from S3 + CloudFront
Cost≈ $0–3 / month at your use (free allowances: 1 M Lambda calls, 25 GB DynamoDB)
Code changeLarge: server split into functions; data rewritten for DynamoDB. One item max 400 KB, so very big cards (today up to 5 MB) must be split or moved to S3
LearnLambda, API Gateway, DynamoDB data modelling, infrastructure as code (SAM/CDK)
Good
  • Almost free for you and friends
  • Scales by itself if it goes viral
  • No server to patch
Watch out
  • Biggest rewrite
  • Cold starts: first request after a quiet spell can take ~0.5–1 s
  • Harder to test locally

4Cloudflare: Workers + D1 + R2 Runs close to every user

ServerCloudflare Workers (JavaScript at the edge, near each user)
DatabaseD1: SQLite run by Cloudflare, so most of our SQL stays the same (10 GB max)
FilesR2: like S3 but no fee when people download/view files
Cost≈ $0–5 / month (Workers paid plan $5; R2 first 10 GB free)
Code changeLarge: Workers have no Node file system or node:sqlite; the server is rewritten for Workers, but the SQL and logic carry over
LearnEdge computing, Workers, D1, R2, Cloudflare DNS (your domain could move there too)
Good
  • Fast everywhere, cheap, generous free tier
  • No download fees for images and videos
  • Free HTTPS and DDoS protection
Watch out
  • Not AWS (if learning AWS is the goal)
  • Worker limits: CPU time per request, request body size for uploads

5Backend-as-a-service: Supabase Least server code

ServerSupabase gives sign-in, a ready-made API and realtime; tiny extra functions only for link previews
DatabaseManaged PostgreSQL with row-level security rules instead of our own checks
FilesSupabase Storage (built on S3) with per-user access rules
CostFree tier is 500 MB DB + 1 GB files (you have 2.9 GB), so Pro ≈ $25 / month
Code changeLarge: replace our accounts, API and checks with Supabase's; data moved to Postgres
LearnPostgres, row-level security, auth providers (Google sign-in becomes easy), realtime sync
Good
  • Google / GitHub sign-in and password reset nearly free
  • Realtime: edits could show on other devices instantly
  • Least code to maintain
Watch out
  • Locked to one provider
  • Security depends on writing the rules right
  • Pro plan cost from day one with your files
